# 航天开源知识研究—转化路线｜Research Roadmap

> 版本 V0.1，2026-10-19。排序是**依赖关系和工作优先级**，不是保证完成日期。对外部资料的研究可持续推进，但必须以真实证据更新状态。

## 0. 当前决策

采取**知识库优先、隔离验证、谨慎迁移、实物门禁不变**的策略：

1. 先建立可信的来源、证据标记与版本锁定机制；
2. 优先处理软件数据有效性、接口、仿真可追溯和 CAD 输入契约；
3. 不因大型上游项目成熟便盲目整体迁移；
4. 优先利用现有 AI-rocket、AeroForge 工具和测试设施，而非创建无必要的新平台；
5. 未经审批不触碰动力/飞行硬件；R2 依然限于断电观察、静态测量准备及纯软件工作。

## 2. 首批可执行研究任务（无外部硬件和付费调用）

### TASK-KB-001（P0）：锁定上游版本与复现工作边界
- 为 GH-01～GH-05 记录经官方发布的 tag、精确 commit、Python/C++ 依赖、系统要求与 license 文件哈希。
- 记录上游最小运行示例和测试命令，但不急于安装复杂运行时。
- **交付**：5 张完整的 `research-record-template.md` 实例；比“已读 README”多至少一个代码或方法层来源。
- **验收**：每个技术断言都可沿链接/版本复查；若无法运行，明确原因。

### TASK-KB-002（P0）：软件异常数据语义
- 从 `R0-005` 与 `R1-002` 出发明确空读、短读、超时、过期与不合法数的区别。
- 先写纯软件测试数据和预期状态；不改变生产控制逻辑。
- **交付**：可审查的输入—预期结果矩阵及原生测试设计。
- **验收**：软件异常不被误判为正常数据，测试路径与实际动作执行路径隔离。

### TASK-KB-003（P0）：仿真证据包
- 审核 `dynamics_sim/` 中符号/坐标/单位及 `aero_sim/` 的历史假设边界。
- 建立版本、输入 SHA256、随机种子、单位、模型 ID、预期用途和输出摘要清单。
- **交付**：run-manifest 规范与无动力解析基准对照。
- **验收**：同版本/同输入/同环境可独立复算；不能验证则显式标记。

### TASK-KB-004（P0）：CAD 验证不虚报
- 根据 `R0-012` 设计故意失败的离线几何检查测试；
- 基于 R2 现有数据字典，不提供没有测量依据的正式尺寸。
- **交付**：几何失败样本与验证命令非零退出要求。
- **验收**：验证程序不得“内部失败、命令外部 PASS”；不改变制造放行。

### TASK-KB-005（P1）：AeroForge 受控知识转化
- 研究卡和候选变更分离；每个变更需需求 ID、来源、风险、可复现测试和评审裁决；
- 遵守 [AeroForge 原项目定义](https://github.com/guo6x/aeroforge-engineering-os/blob/main/README.md) 的审批隔离与版本冻结原则。
- **交付**：只读知识索引与建议提案合同，暂不改造 AeroForge 的生产逻辑。
- **验收**：研究结论不会被伪装成已批准工程事实；不能由 AI 直接放行。

## 3. 一张研究卡要做到什么程度

每张研究卡必须有：

- **问题**：解决当前哪一个具体 issue / 未知工程决策？
- **原始资料**：仓库链接、精确 SHA/tag、文件位置、官方标准版号及查阅时间。
- **功能事实**：上游源码或官方资料实际说明了什么？哪些仍只是宣传或假设？
- **约束**：模型适用域、环境依赖、平台资源、许可证/外部资产、维护负担。
- **实验设计**：最小可复现输入、可观测输出、通过/失败标准及不可推出的结论。
- **工程落点**：映射现有模块、无需做的事情、收益/成本/风险与回退方案。
- **裁决**：`REJECT/DEFER/PROPOSE`，并保留任何负面证据。

缺任何关键字段不得上升为 `REPRODUCED` 或 `TRANSFER_PROPOSED`。

## 4. 持续积累，不制造“科研假进度”

可以不断检索 GitHub 新仓库、issue、上游变更、论文和标准，但以下动作必须有明确触发：
- 出现已发布新 tag 或重要安全/工程更新 → 复查相应研究卡；
- 项目 baseline 或约束变化 → 重新计算技术适配性；
- 软件实验完成 → 附独立证据日志及精确输入；
- 新发现与旧结论冲突 → 保留历史版本，并建立 correction 记录。

**不能仅靠 GitHub Star、最新提交、热门讨论来升级工程可信度。** 外部更新是研究触发器，不是验收结论。

## 5. 安全和质量停止条件

以下任一情况立即停止“自动适配”，转为研究记录/问题阻断：
1. 需要接通 EDF、执行舵机动作、推进系统操作或自由飞行；
2. 输入物理尺寸、质量、CG/惯量、力学工况为 `UNKNOWN`；
3. 模型坐标系、单位或控制正负定义不明；
4. 需要修改现有安全状态机，但未有隔离回归与独立评审；
5. 许可证、第三方依赖或版权义务不明确；
6. 结果无法重复或无法解释报告中的异常；
7. 研究资料与当前 `engineering/` 权威文件相冲突且没有新证据。

## 6. 后续扩展路线

- 初期：开源飞控、仿真、CAD 与系统可靠性。
- 中期：结构、制造工艺、气动、热、电源、地面支持、工程经济。
- 长期：公开推进科学、轨道/任务、载人航天系统工程、工业化质量与供应链。
- 每个方向都坚持**公开来源 + 专业判断 + 独立验证 + 受控转化**。并明确区分“知识参考价值”和“现阶段应该开发的功能”。
