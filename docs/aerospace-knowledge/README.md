# Project Ad Astra — 航天工程长期知识库

> 创建：2026-10-19 ｜仓库审阅基线：`AI-rocket@66861c7c9f0d468e81a2e09c7a354ed6058dd20f`（main）  
> 文档性质：**研究资料与受控技术建议**。不构成实物验证、飞行放行、产品认证或生产技术规范。  
> 当前物理阶段的唯一权威入口仍是 [`../../engineering/README.md`](../../engineering/README.md) 与 [`current-baseline.yaml`](../../engineering/current-baseline.yaml)。

## 目的

把 NASA、ESA/ECSS、开源软件团队、大学火箭团队及中国公开航天工程资料中的**可核实知识**转化为 Ad Astra 的长期研发资产。不是收藏链接，而是从原始依据到项目决策形成完整追溯：

`来源/版本 → 适用条件 → 原理/设计取舍 → 项目差距 → 隔离实验 → 证据 → 采纳/拒绝/暂缓 → 后续复查`。

本知识库同时为 `AI-rocket` 的工程试验线以及 `AeroForge` 的数字工程平台提供参考；**本仓库中的研究意见不得自动改变 AeroForge、飞控或实物的工作状态**。

## 十二个长期工程方向

1. **系统工程**：任务定义、需求分解、V 模型、接口控制、技术评审、配置管理。
2. **结构/材料/制造**：载荷、振动、疲劳、材料与制造、质量属性、几何公差。
3. **航电与飞行软件**：嵌入式接口、遥测、命令、传感器健康、软件架构。
4. **可靠性与验证**：危害识别、故障模式分析、测试可追溯、软件/硬件证据隔离。
5. **飞行动力学**：坐标系、六自由度模型、惯性参数、动态响应。
6. **状态估计和控制**：误差模型、估计器、故障降级、数值鲁棒性；仅在仿真与经授权的安全边界内讨论实施。
7. **空气动力学与热学**：气动参数来源、流动条件、热环境与模型适用边界。
8. **推进科学基础**：推进系统类型、基础性能定义、系统工程与安全合规；不以本库发放高能推进实操许可。
9. **电源/热管理**：能量与功率预算、电气接口、保护、热设计。
10. **地面支持与任务操作**：操作流程、检查表、审查门、应急和记录。
11. **轨道与空间任务**：轨道力学、任务分析、环境模型、任务约束；对 R2 为远期方向。
12. **航天产业与工程经济**：研发投入、供应链、质量成本、知识产权、许可与合规。

## 研究状态，不混用工程验证状态

- `DISCOVERED`：仅发现资料，尚未核对原始内容。
- `SOURCE_CHECKED`：已查公开 README、文档或许可/目录，确认其公开宣称与资料结构。
- `ANALYZED`：已针对一个项目问题阅读相关模块/方法并形成可检验假设。
- `REPRODUCED`：锁定版本、依赖、命令和输入，独立运行并留存通过/失败日志。
- `CROSS_CHECKED`：以不同模型/解析基准/测量进行适用范围内的交叉验证。
- `TRANSFER_PROPOSED`：形成项目适配提案，尚未批准合入。
- `ADOPTED_SOFTWARE`：通过项目自身代码审查、回归和验收，不等于硬件合格。
- `REJECTED` / `DEFERRED`：有可复核的原因与复查条件。

初始研究的最高等级仅为 `SOURCE_CHECKED`，少数条目具备初步分析；**没有开展第三方项目构建复现、硬件通电试验或控制器合格认证**。

## 证据权威顺序

1. 当前项目的 [`engineering/`](../../engineering/) 实物/参数/验证底账（最高）。
2. 版本化项目源码与可重复验证日志。
3. 原项目官方仓库源代码、发布记录、文档、许可证、官方标准原文。
4. 可靠论文、交叉验证研究与第三方问题讨论。
5. 社区教程、视频和个人经验（只能提供线索）。
6. AI 总结与推测（不得独立作为事实或放行依据）。

所有非项目原始数值都必须标注来源、适用构型、版本和单位。若实物参数仍为 `UNKNOWN`，不得用历史 CAD、产品网图或模拟参数补填。

## 本次边界

- 允许：公开技术研究、文献比较、独立软件实验设计、故障注入用例设计、静态/断电的测量准备、文档归档。
- 不自动授权：动力系统采购/改造、推进剂/点火、通电 EDF 推力试验、自由飞行、实物 PID 调参、放行或产品认证。
- **接受真实失败**：测试不通过、资料不足、许可证不清晰时保留 `BLOCKED`，不为了“完成研究”填造结论。

## 更新机制

新增材料 → 用 [研究卡模板](research-record-template.md) 写研究卡 → 与 [差距矩阵](ad-astra-gap-matrix.md) 建立双向链接 → 记录独立实验 → 受控评审 → 决定是否进入产品和工程分支。每次修订记来源检索日期、原仓库 commit/tag、具体文件路径、测试环境及评审人。

长期目标是积累可以持续复用的知识和判断标准，而不是把所有开源项目直接合并进一个庞大且不可维护的代码库。
